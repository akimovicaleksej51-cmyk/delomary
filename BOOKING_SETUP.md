# Подключение бронирования и заявок Loony Room к Telegram и email

В этом архиве файлы для вашего репозитория `delomary`:

- `index.html` — обновлён: без номера дела, с компактной галереей и
  навигацией по фото, форма брони реально отправляет данные, поле email в
  Loony Room тоже реально отправляет данные, убран чёрный прямоугольник в
  тексте Loony Room.
- `api/book.js` — серверная функция для формы брони квеста, шлёт заявку в
  Telegram-бот квеста.
- `api/lead.js` — серверная функция для email из Loony Room. Делает две
  вещи: (1) шлёт вам заявку в **отдельный** Telegram-бот/чат (специально не
  смешиваем брони квеста и заявки на комнату), и (2) сразу отправляет
  человеку письмо на его почту — «спасибо, вы в списке». Текст письма —
  черновик, его легко поменять (см. раздел «Текст письма» в конце).
- `package.json` — нужен, чтобы Vercel правильно запускал функции из `api/`
  (если у вас уже есть свой `package.json` в репозитории — просто добавьте
  в него строку `"type": "module"`, остальное не обязательно).

`assets/` и `README.md` не трогайте — они не менялись.

## Бот для брони квеста (если ещё не настроен)

1. Бот через @BotFather → `TELEGRAM_BOT_TOKEN`.
2. chat_id → `TELEGRAM_CHAT_ID` (см. способ ниже).

## Бот для заявок Loony Room (уведомление вам в Telegram)

Вы создаёте второго бота специально для этого — переменные для него
называются **по-другому**, не перепутайте:

1. **Создать бота** через @BotFather (`/newbot`) → получите токен, это
   будет `LOONY_BOT_TOKEN`.
2. **Узнать chat_id**:
   - Если это личный чат с ботом — напишите ему `/start`, затем откройте
     `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите
     `"chat":{"id":ЧИСЛО,...}`.
   - Если добавили бота в группу — отправьте в группу `/start` (важно
     именно со слэшем), затем так же откройте `getUpdates`. Для группы
     число будет **отрицательным** (например `-1004396498637`).
   - Если `getUpdates` возвращает пусто — отключите приватность бота:
     @BotFather → `/mybots` → ваш бот → **Bot Settings** → **Group
     Privacy** → **Turn off**, и повторите попытку.
   Это значение — `LOONY_CHAT_ID`.

## Письмо на почту клиенту (новое)

Это отдельная система — она не имеет отношения к Telegram-боту выше, и
работает независимо. Для отправки писем используется сервис
**Elastic Email** — его подтверждение отправителя требует только переход
по ссылке в письме, без телефона и без домена (SendGrid просит SMS-код и
не принимает белорусские номера, поэтому не подошёл).

1. Зарегистрируйтесь на **elasticemail.com** (Sign up — регистрация по
   email, телефон не спрашивают).
2. Подтвердите отправителя: **Settings → Domains → Verify email**.
   Впишите свой обычный email (например ваш gmail) — придёт письмо со
   ссылкой, перейдите по ней. Этот email и есть `ELASTICEMAIL_FROM` — с
   него будут уходить письма клиентам. Домен подтверждать не нужно.
3. Создайте ключ: **Settings → API → Create additional API Key** (или
   в разделе Security/API Keys, в зависимости от версии интерфейса) →
   скопируйте значение. Это `ELASTICEMAIL_API_KEY`.

Если эти две переменные не заданы — форма всё равно продолжит работать
(заявка по-прежнему придёт вам в Telegram), просто письмо клиенту не
отправится. Так что ничего не сломается, если решите подключить это
позже.

## Что сделать с файлами

1. **Залить файлы** из этого архива в репозиторий `delomary` на GitHub
   (Add file → Upload files, с подтверждением перезаписи `index.html` и
   `api/lead.js`).
2. **Прописать переменные** в Vercel → Project → Settings → Environment
   Variables:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `LOONY_BOT_TOKEN`
   - `LOONY_CHAT_ID`
   - `ELASTICEMAIL_API_KEY` (для письма клиенту)
   - `ELASTICEMAIL_FROM` (для письма клиенту)
3. Сделать **Redeploy** (Vercel → Deployments → ⋯ → Redeploy), чтобы
   функции подхватили новые переменные.

## Проверка

- Форма брони: заполните имя и телефон, нажмите «Отправить заявку на
  бронь» — в Telegram-боте квеста должно появиться сообщение с деталями.
- Loony Room: впишите свой email, нажмите «Сообщить мне первому» — в
  Telegram-боте Loony Room должно появиться сообщение с этим адресом, и
  на саму почту должно прийти письмо (проверьте и папку «Спам» — для
  новых отправителей это нормально первое время).
- Ошибка «форма временно не работает» / «попробуйте ещё раз чуть позже» —
  значит для соответствующей формы не заданы (или заданы с опечаткой)
  переменные окружения.

## Текст письма (черновик — отредактируем)

Сейчас клиенту уходит вот такое письмо:

> **Тема:** Вы в списке — Loony Room скоро откроется
>
> Здравствуйте.
>
> Спасибо, что оставили свой адрес — вы в числе первых, кто узнает об
> открытии новой комнаты Loony Room от квеста «Дело Мэри. Скажи им, что я
> здесь».
>
> Как только будут готовы дата запуска, цена и расписание — мы напишем
> вам сюда же, на этот адрес, и вы сможете забронировать место раньше
> остальных.
>
> До встречи по ту сторону двери.
>
> — Loony Games

Это черновик для проверки, что всё технически работает. Чтобы поменять
текст — присылайте новый вариант, я перепишу его прямо в `api/lead.js`
(тема письма и сам текст — в самом начале файла, переменная
`EMAIL_SUBJECT` и функции `buildEmailText`/`buildEmailHtml`).

## Если Elastic Email тоже не подойдёт

Если и здесь возникнет похожая проблема — есть ещё запасные варианты
(Mailjet, Postmark, SMTP2GO), у них тоже есть подтверждение через один
email без домена. Просто напишите, что не сработало, и я перепишу
`api/lead.js` под другой сервис — сама логика (проверка адреса,
уведомление в Telegram, письмо клиенту) не изменится, поменяется только
блок отправки письма.
